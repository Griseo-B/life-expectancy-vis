寿命变长，是所有国家一起变好吗？

交互式可视化设计说明与报告

许珀铭 · 2024201576 · 单人完成 · 2026 年 11 月

  • 数据：World Bank, World Development Indicators，1960–2019
  • 规模：208 个国家 × 60 年，11,780 条「国家 × 年」记录
  • 在线作品：griseo-b.github.io/life-expectancy-vis
  • 报告页面：griseo-b.github.io/life-expectancy-vis/report.html
  • PDF 版：报告.pdf

1. 要回答的问题

1960 到 2019 年，各国出生时的预期寿命从国家中位数 54.7 岁涨到 74.2 岁。这个数字很整齐，但它藏着一个问题： 是所有国家一起变好，还是少数国家把平均值拉高了？

作品围绕三个更具体的问题展开：

  1. 六十年里，寿命的整片分布是不是一起右移？国家之间的差距在缩小还是固着？—— 最高与最低的差距 1960 年是 45.3 岁，1990 年 45.4 岁，几乎没动：前三十年最高的一头只涨了 5 岁（73.5→78.8）， 最低的一头也只从 28.2 抬到 33.4。真正收窄发生在 1990 年之后，最低值在 2019 年升到 53.3，差距降到 31.8 岁。
  2. 有没有国家在这段时间里掉头向下，掉多久，回来了没有？——2019 年仍有 2 个国家低于自己的 1990 年（莱索托、斯威士兰）。
  3. 寿命、收入、生育率一起移动时，看到的是不是同一个故事？

作品不试图回答因果问题。数据里没有租金、冲突、疫情、卫生支出，图只能说明“一起变化”，不能说明“因为谁”。

2. 数据与范围

  • 用到的四个指标：出生时预期寿命（岁）、总和生育率、人均 GDP（2017 年不变价国际元，PPP）、人口。

  • 189 个国家的寿命序列 60 年齐全，其余 19 国有断年；绘图时跳过缺值，不做插补。
  • 收入组是“当前的分类”，不是当年的分类，不能拿它说“1960 年这个国家是低收入”。委内瑞拉在当前分类里没有收入组，因此一旦启用收入组筛选就会落选。
  • 地区 7 类，包含中国香港、格陵兰、开曼群岛等附属地区，所以“国家”更准确的说法是“经济体”。
  • 所有国家一票，未按人口加权。2019 年国家中位数 74.2 岁，人口加权的世界值是 72.7 岁——两者不能互换，图上标注的一律是国家中位数。

3. 设计决策

3.1 视觉编码

维度编码理由
预期寿命纵轴位置位置是判断定量数值最准确的通道，也是全图的主线
生育率 / 人均 GDP横轴位置两个连续量都用位置，不做双轴、不做面积
人口圆面积面积表达数量级；半径用开方标度，避免把 14 亿画成 1 万的 14 万倍
地区颜色7 个类别，定性色板，一个维度只用一次颜色
1960 年的地区中位数空心圈 + 细连线作为参照，不与当前值抢视觉权重
1960 年的国家中位数一条虚线给“一起变好”一条可读的基线：看谁从线下走到线上
起点年份的位置同色空心小圈1960 年的位置留在原处（GDP 模式为 1990 年），看每个国家走了多远

人均 GDP 用对数刻度：数据从 437 到 161,971，跨约 2.7 个数量级，线性刻度会把低收入国家全部挤在左边。 轴域取 400–200,000，把全部观测包在中间，因此“不筛选”与“选满全范围”是同一个状态（§3.4）。

空心小圈随年份推进淡入：读 1960 年时看不见，读到 2019 年时下半张图不再是空白，而是六十年前的世界。 这也顺手解决了固定纵轴带来的空档——时间在走，起点留在原地。

3.2 布局与多视图协同

页面三块，共用一份选择与同一个年份：

  • 主图（左，约 62% 宽）：生育率—寿命散点，带起点空心圈、国家中位数虚线、刷选框。
  • 右上地区点图：每个点是一个国家，竖线是地区中位数，空心圈是 1960 年；负责“地区之间的分布与差距”。
  • 右下对比面板：搜索框 + 被选国家的实时履历（寿命、生育率、GDP、人口与 1960 年的差）。

主图回答“哪个国家在哪”，地区图回答“组与组差多少”，对比图回答“这个国家自己怎么走过来的”。 三者是同一份数据的三种切分，所以任何一次选择、任何一帧年份都必须同时生效。

标题下还有三个随年份变的数字：国家中位数、寿命 ≥ 70 岁的国家数、最高与最低相差。 它们正好是 §1 三个问题的直读数，用文字占掉一部分信息量，省下图形空间给分布本身。

3.3 交互技术

类别交互任务价值
时间时间轴 + 播放动态查询。时间不做第三个空间维度，用动画换空间，避免三维散点
选国家单击圆点精确地加入 / 移出对比；与刷选互补
选国家拖框刷选圈出一片区域，成批选中国家，联动右侧面板
选国家按名字搜索散点里 200 多个国家太密，输入中文名、英文名或三位代码即可加入对比
选国家按指标筛选定住年份后，用 GDP 范围、生育率范围、收入组筛出国家；不符合的变淡
选国家清空全部对比面板里一键清空，不必逐个点 ×
看细节悬停提示按需细节（details on demand），逐国读数

换视角点地区名动态过滤，七个地区之间快速切换焦点

交互次序按 Shneiderman 的“先概览、再缩放过滤、最后按需细节”组织：默认画面就是 2019 年的全量概览， 下拉框、地区焦点与筛选都是收窄手段，提示框与对比面板才是细节。

3.4 把国家选进对比的四个入口

散点图里有 200 多个圆，“选国家”这一件事被拆成四种粒度，对应四种不同的心智状态：

  1. 单击圆点——已经看见目标，要精确加入或移出。
  2. 拖框刷选——不知道具体是谁，只知道“左上角这一片”或“高生育率低寿命那一群”。
  3. 按名字搜索——知道是谁但找不到它：支持中文名、英文名、ISO3 代码，中文名还支持跳字匹配（“新加”命中新加坡）， 下拉最多给 7 条候选；↑ ↓ 移动、回车加入、Esc 收起；已选中的条目会标出来，避免重复添加。
  4. 按指标筛选——知道条件不知道名字：人均 GDP 区间、生育率区间、收入组，三者可叠加； 面板实时显示命中国家数，并可一键把它们全部加入对比。

为什么筛选是“变淡”而不是“删除”。 如果筛选后直接隐藏不匹配的国家，整张图的形状会随条件跳变，读者失去“这些国家去哪了”的参照，也就看不出条件把谁筛掉了。 变淡保留了全量的轮廓（城市群的形状、地区之间的相对位置都还在），只把注意力导向匹配项； 不匹配的国家仍然是可悬停、可点击的，也就是说筛选是一种“高亮”，不是一次“删库”。

为什么范围既能拖又能填。 拖选适合探索——先拖一段看有多少国家；输入框适合复核——“GDP 5000 到 20000 到底有多少个”需要精确边界。 两者共用同一份范围状态：拖动轴会即时写入输入框，输入框失焦或回车会反写轴上的刷选框。 输入过程中不覆盖正在编辑的框（否则光标会跳），空值解释为不设限，越界值夹紧到轴域，上下限填反了自动交换。

1990 年以前为什么暂停 GDP 条件。 如前所述，1990 年前 GDP 全空。如果照常计算，任何 GDP 条件都会让全部国家落选，图上只剩一层极淡的残影——用户会以为作品坏了。 所以 t < 1990 时跳过 GDP 条件、保留生育率与收入组条件，并在面板里写清楚“人均 GDP 自 1990 年才有记录：这一年 GDP 条件暂不生效”。 宁可少筛一项，也不给一个看不懂的结果。

筛选条件为什么跟着年份走。 条件是“这一年”的快照，播放时逐年重算，匹配数会随年份变化。这一条不是为了炫技： 同一个 GDP 门槛在 1960 与 2019 命中的国家集合完全不同，集合的移动本身就是在读发展。

3.5 考虑过但放弃的方案

  • 地图（choropleth）：国家面积差异太大，颜色还要承担连续变量，一个图放不下两个维度，而且会把读者的注意力引向地理而非分布。
  • 1960 与 2019 的小多图 / 哑铃图：只能看两个端点，中间的 58 年被折叠掉；而这 58 年恰好有南部非洲的下跌和回升。
  • 只画地区中位数折线：干净，但会把组内差异全部抹平（课程 EDA 里已经证明低收入组内部差距极大），而这正是本作品要问的问题。
  • 默认用人均 GDP 作横轴：更符合“收入—寿命”的经典叙事，但 GDP 只有 1990 年以后，会把一半时间轴变成空白。因此默认横轴取生育率（1960–2019 全覆盖），把 GDP 做成可切换的第二个视图，切换时时间轴自动缩到 1990–2019。这是数据可得性倒逼的设计取舍，也是作品里最明显的一处妥协。
  • 筛选后隐藏不匹配的国家：见 §3.4，会破坏概览的连续性与可追溯性。
  • 200 多项的国家多选框：比搜索框更“完整”，但在一长串列表里找“纳米比亚”比输入两个字慢得多，也占掉了对比面板的高度。
  • LLM 自然语言查询：见 §3.6。

3.6 关于大语言模型

作业允许把 LLM 作为交互代理。这一版没有接入，理由是：

  1. 作品是纯静态站点，没有后端，调用公共 API 只能把密钥写在前端，等于公开；
  2. 自然语言解析出的过滤条件一旦不确定，“图上为什么少了几个国家”就无法复核；本作品其余交互都是确定性的，加一个概率性入口会破坏这种可复核性；
  3. 评分标准把“错误或功能失效”计为扣分项，而数字幻觉正是这类作品最容易翻车的地方；
  4. 公用 Web API 不稳定，容易导致调用失败，也会放大模型幻觉与出错。

替代方案是确定性的动态摘要：标题下那行文字（国家中位数、比 1960 年高多少、还有多少国家低于自己的 1990 年）由当前年份算出， 全部数字来自同一份数据，没有模型参与。新增的筛选面板走同一条原则：条件由人给，结果由代码算，匹配数当场可数。

若继续做，可行路径是让 LLM 只负责把自然语言变成结构化查询（指标、年份、阈值），数值与图形仍由本地代码计算， 并要求它不直接输出任何数字；同时由用户自备 key。前者能保住可复核性，后者会显著提高使用门槛，所以这一版没有采用。

最花时间的三件事：

  1. 数据可得性带来的返工。 最初把人均 GDP 设为默认横轴，写完才发现 1960–1989 全空，动画前半段是一张空图。改成生育率默认、GDP 可切换之后， 时间轴范围也要跟着变，这一处改动牵连到滑块、刻度、叙述文案和三个视图的年份同步。
  2. 播放时的视觉连续性。 整步跳会顿，插值解决了位置，但引出了“屏幕上不是真实观测”的解释成本；同时它对性能提出要求， 最后的写法是只更新已有元素的属性、不重建选择集，一次重绘才压到毫秒级。
  3. 筛选与其它交互共用一套状态。 筛选范围、输入框、轴上的刷选框、年份、播放是五个会互相触发的输入源，最初互相覆盖， 出现过“打字打到一半光标跳走”“播放时筛选框自己回弹”。最后的做法是：任何程序化写入都不在用户正在编辑的元素上执行，只在失焦、回车或强制同步时写回。

6. 已知局限

  • 每个国家一票，人口大国与小岛国权重相同；要谈“全世界的人”，应改看人口加权值（2019 年为 72.7 岁）。
  • 收入组是当前分类，带后视镜偏差；委内瑞拉没有收入组，启用该项筛选必然落选。
  • 动画在相邻年份之间插值，屏幕上某一帧的位置可能不对应任何一年的真实观测。
  • 小国（如加勒比、太平洋岛屿）样本少，容易在视觉上被大圆遮住；本作品按人口从大到小绘制，小圆在上层。
  • 刷选或筛选可以一次加入上百个国家，但对比面板最多显示 12 个（最近操作的优先，其余按人口），轨迹最多画 14 条；其余的只能靠主图高亮与提示框查看。“清空全部”能一次性退出这种状态，但不能逐个管理被省略的那些。
  • 筛选只支持三个维度（GDP、生育率、收入组），不支持按地区、按人口或按“寿命变化量”筛选。
  • 移动端关掉了框选，批量选择只能靠筛选面板；这是为保留页面滚动做的让步。
